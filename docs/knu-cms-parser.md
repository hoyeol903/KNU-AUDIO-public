# KNU CMS 오프라인 파서

2026-09-30 구현. 이 파서 자체는 HTML만 처리한다. 이후 사이트 요청·첫 페이지 저장은 `collector/run.py`에 연결했다(`docs/collection.md`). 페이지 순회도 구현했다. 일일 자동 수집은 아직 구현하지 않았다.

## 구현 범위

`collector/knu_cms.py`의 `parse_list(html, url)`은 글 ID·제목·게시일·상세 URL을 반환한다. `mv_data`의 Base64를 풀어 `idx`를 사용하며 화면 순번 `listNo`는 사용하지 않는다. 고정 공지와 일반 목록에 중복 노출된 글은 합친다.

`parse_detail(html, url)`은 제목·게시일·본문·본문 상태·첨부 파일 이름/주소를 반환한다. 문단·줄바꿈을 유지하고 인라인 태그로 나뉜 글자는 이어 붙인다. PDF 뷰어의 설치 안내는 본문에서 제외한다. 이미지 전용·첨부 전용·정상 빈 본문을 구분하고, 텍스트 없는 임베드 본문은 `needs-review`로 남긴다.

`to_notice(list_item, detail, board_id=..., channel_ids=...)`는 목록·상세의 글 ID, 제목, 게시일이 일치하는지 확인한 후 기존 `store.upsert_notices()` 입력으로 변환한다. 사이트 구조가 없거나 날짜·글 ID가 잘못되면 `ParseError`를 발생시킨다. 정상적인 “등록된 내용이 없습니다.” 표식이 있는 목록만 빈 배열로 반환한다.

마감일 자동 추출은 아직 구현하지 않았으므로 `deadline`은 null이다. 날짜와 접수 시간은 본문에 원문대로 보존한다. 첨부 링크는 상세 파싱 결과에서 제공하지만 현재 영구 저장 계약에는 첨부 필드가 없어 DB에는 저장하지 않는다. PDF/HWP 파일 내용과 이미지 OCR은 처리하지 않는다.

## 보강점과 다음 후보

1. **다음 추천: 실제 요청 계층 + 한 게시판 수집.** 국어국문학과 한 곳에서 목록 → 상세 → store를 실행한다. User-Agent, 같은 서버 요청 간격 1초 이상, 재시도 최대 2번, 타임아웃, 실패 기록을 함께 구현한다. 원문 검증 후 다른 KNU CMS 게시판으로 확대한다.
2. **다른 학과 상세 검증과 페이지 순회.** 이번에는 목록 3곳·상세 1곳만 확인했다. 스킨 차이, 페이지 경계, 지난 공지 처리, 수정 공지 재확인 범위를 결정한다.
3. **첨부 저장과 마감일 처리.** 첨부 필드는 먼저 계약을 합의한다. 마감일은 복수 기간·연도 생략 등 애매한 문장을 추측하지 않고 검토 대상으로 남기는 방식으로 만든다.
4. **다른 게시판 틀 지원.** 조사된 채널 수와 필수 채널 우선순위에 맞춰 그누보드·전자공학부 등 별도 파서를 추가한다.
5. **브리핑 입력 선정.** 저장 DB에서 오늘 신규/마감 알림을 골라 채널별 items.json을 만든다. 첫 실행에 과거 공지가 모두 신규 브리핑으로 나가지 않도록 초기 적재 정책을 먼저 정한다.
