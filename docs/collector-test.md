# 수집기 HTML 테스트 화면

프로젝트 폴더에서 실행한다.

```bash
python -m collector.preview
```

현재 로컬은 `/opt/anaconda3/bin/python3 -m collector.preview`를 사용한다. 브라우저에서 http://127.0.0.1:8765 를 연다. 다른 포트는 --port로 지정하며 종료는 Ctrl+C다. HTML 원본은 tools/collector-test.html이다. HTML 파일을 바로 열면 실행 안내가 나온다. 실제 Python 규칙을 호출하므로 로컬 테스트 실행창이 필요하다. 이 서버는 개발 중 시험용이며 서비스 운영 서버를 추가한 것이 아니다.

## 눌러볼 것

1. 실제 저장 자료: 내 학과를 선택한다. 필수 채널이 자동 선택된다. 채널 검색으로 선택 채널과 식당을 추가한다.
2. 오늘 자료 확인: 저장 DB를 읽어 실제 선정 규칙으로 결과를 보여준다. 학교 사이트를 새로 호출하지 않는다. 미저장·오늘 확인 없음·요청 실패·본문 미확인을 구분한다.
3. 수학과 신규 공지 예시 보기: 2026-10-01 저장 자료에서 선정 공지 3개를 확인할 수 있다. 이후 날짜에는 당일 확인/선정 조건에 따라 결과가 달라진다.
4. 선정된 공지/빠진 공지/전체 공지를 고른다. 제목·ID로 검색하고 이전/다음으로 넘긴다. 공지 제목을 누르면 원문·판정 이유·발견/확인 시각·본문이 열린다.
5. 결과 JSON 다운로드: 화면에서 고른 채널의 입력 자료 사본을 다운로드한다. 저장소의 items.json을 덮어쓰지 않는다.
6. 가상 조건 시험: 새 공지, 마감 3일 전, 이미 마감, 이미지 본문, 오늘 확인 실패, 초기 과거 적재 버튼을 눌러본다. 날짜·본문·마감일·발견/확인 시각을 수정하고 시험한다.
7. 본문에서 마감일 찾기: 연도까지 적힌 신청/제출 마감을 입력해 추출 결과와 근거를 확인한다. 애매한 날짜는 비워둔다.

실제 자료 화면은 현재 한국 날짜만 판정한다. 다른 날짜 시험은 가상 조건 화면에서 한다. 과거 자료를 최신 DB로 완전히 재현한 것이라고 표시하지 않는다.

Python의 collector.daily_items.decide_notice와 build_items를 그대로 사용한다. HTML에서 다른 선정 규칙을 만들지 않았다. API는 127.0.0.1에만 열며 저장소 읽기 전용이다. 회원가입·로그인·실제 크롤링 실행·설정 저장·DB 변경은 없다. 실제 웹 플레이어와 별개다.

테스트 174개 통과. 브라우저에서 실제 수학과 선정 3개, 가상 새 공지 선정·마감 3일 전 재안내·원문 마감일 추출을 확인했다. 자동 검사에서 시험 전후 실제 DB 바이트가 같은지도 확인한다. 저장 자료가 없는 채널은 자료가 없다고 표시하므로 전수 수집 성공을 뜻하지 않는다.

## 앱 모양 테스트 화면

같은 테스트 실행창에서 http://127.0.0.1:8765/app 을 연다. HTML 원본은 tools/app-test.html이다.

1. 이름을 적고 학과를 검색해 고른다.
2. 필수 탭에서 학교 공통·내 학과 필수 게시판이 자동 포함된 것을 확인하고, 선택 탭에서 선택 게시판과 식당을 켠다.
3. 홈에서 날씨·학사일정·내 게시판 목록을 본다. 게시판을 누르면 오늘 소식과 저장된 최근 글 30개가, 글을 누르면 본문과 원문 링크가 나온다.
4. 게시판 설정에서 선택을 바꾸고 저장한다.

이름·학과·선택 게시판은 이 브라우저에만 저장한다. 위 테스트 화면과 같은 읽기 전용 API를 쓰므로 학교 사이트 요청과 DB 변경이 없다. 음성 재생은 없으며 실제 웹 플레이어와 별개다. 수집을 시작하지 않은 게시판은 "아직 수집 전"으로 표시한다.
