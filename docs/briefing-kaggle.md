# Kaggle GPU 브리핑 실행

## 검수 실패 대본 확인

`output/review.json`과 비공개 Kaggle 결과의 `diagnostics/review.json`에는 실패한 생성 시도별 대본과 검수 사유를 기록한다. 대본의 이메일·전화번호·학번·주민번호 형식과 등록된 욕설은 가려서 저장한다. 숫자 사유에는 원문에 없는 것으로 판정된 정규화 숫자·시간 값을, 개인정보 사유에는 패턴 종류와 값을 가린 형식을 남긴다. 이는 검수 판정 기록이며 실제 잘못된 사실·개인정보라고 확정하는 것은 아니다. 현재 정규식이 인식하지 못하는 개인정보는 가려지지 않을 수 있으므로 진단 파일은 공개하거나 저장소에 커밋하지 않는다.

금액은 숫자와 백·천·만·억 단위를 원 단위로 정규화해 비교한다(예: 300,000원 = 30만 원, 1,000만원 = 1천만 원). 금액이 바뀌면 막는다. 전화번호는 일반 숫자 비교에서 제외하고 연락처 규칙으로 별도 차단한다. 한글 숫자만 쓴 금액(예: 삼십만 원)은 아직 정규화하지 않는다. 재생성 횟수는 그대로다. 검토 대본은 앱 출력과 공지 제외 목록에 포함하지 않는다. 이전 실행에서 저장하지 않은 실패 대본은 복원할 수 없으며 같은 공지를 재생성한 결과는 당시 대본과 다를 수 있다.

## 대본 길이 제한

공지 대본은 공백 포함 140자(`briefing/content.py`의 `max_chars`)를 넘기지 않는다. 제한 값은 모델 입력에 `max_chars`로 전달하고, 초안이 넘으면 기존 수정 요청에 길이 지적을 함께 보낸다. 수정본도 넘으면 상한 안에 들어가는 앞 문장만 남기며, 첫 문장부터 넘으면 제목만 안내한다. 뒤 문장을 버리는 단순 절단이라 뒤에 있던 마감·조건은 빠질 수 있다. 날씨 구간의 240자는 참고용이며 강제하지 않는다. 2026-10-09 자료에서는 제한이 적용되지 않아 공지 대본 중앙값이 273자, 최대 692자였다.

## 공지 말투 (2026-10-09)

- 날짜마다 공지 말투 세 가지(차분한 설명형, 친근한 안내형, 생기 있는 라디오형)를 1→2→3 순서로 돌려 쓴다. 같은 날짜를 다시 만들면 같은 말투다. 말투 지시는 표현 방식만 바꾸며 사실은 원문을 따른다.
- 공지 대본의 문장 끝 동사형 합니다체(`안내합니다`, `진행됩니다`, `가능합니다` 등 16개)는 해요체로 바꾼 뒤 검수한다. `안내입니다` 같은 명사형과 문장 중간 표현은 바꾸지 않는다. 바꾼 내역은 검수 보고서의 `ending_normalizations`에 남는다.
- 대본 모델은 `qwen3:4b-instruct-2507-q4_K_M`이다.
- 옛 저장소 PR #62의 일부만 옮긴 것이다. 그 PR의 50자 제한, 원문 근거 대조, 통과 못 한 공지 건너뛰기는 옮기지 않았다.

## 음성 후처리 (2026-10-09)

- 모든 음성은 24kHz로 인코딩한다. 구간마다 24kHz와 48kHz가 섞여, 인사와 날씨를 이어 붙인 구간이 브라우저에서 경계에서 끊겼다.
- 음량은 구간마다 측정한 뒤 같은 방식으로 맞춘다: 목표(-19 LUFS)까지 고정 증폭하고, -2dB를 넘는 순간 피크만 리미터로 누른다. 이전의 loudnorm 2차 처리는 구간에 따라 선형·동적 방식이 갈려 소리 느낌이 달라졌다.
- 구간 끝의 쉼을 0.25초 늘렸다(`added_tail_silence_sec` 0.18→0.43). 인사·날씨·공지가 붙어서 들린다는 의견에 따른 값이다.
- 실제 소리는 Kaggle에서 생성한 결과로 확인해야 한다.

## 초안 수정 흐름

모델 입력의 알려진 연락처·식별정보·비속어 패턴은 먼저 가린다. 초안이 실패하면 동일 생성 모델에 가려진 초안, 문제 값, 관련 원문 인용과 수정 지시를 함께 보내 한 번만 수정한다. 첫 대본만 규칙 검수한다. 수정한 두 번째 대본은 재검수 없이 음성 생성에 사용하며 `revision-unchecked`로 기록한다. 별도 검수 AI는 호출하지 않는다. 검수·프롬프트 버전 변경은 기존 대본 캐시 키에도 반영한다.

시간은 아침·오전·낮·오후·저녁·밤과 바로 이어지는 시간 범위를 정규화한다. 원문의 명시적 `단위:원` 표 아래 독립 숫자 셀도 금액 근거로 사용하며 다음 번호 소제목에서 범위를 끝낸다. 복잡한 표의 열 관계, 단위가 누락된 금액, 날짜·시간의 역할이나 대상·조건의 의미 전체는 검증하지 못한다. 근거가 불명확한 값은 통과 보장을 하지 않고, 수정 요청에서는 추측 대신 해당 표현을 생략하도록 한다. 원문 인용이 존재한다는 사실만으로 의미가 일치한다고 보장하지 않는다.

`Kaggle GPU 브리핑 생성` workflow는 수동 실행과 수집 완료 후 연결을 지원합니다. 기존 CPU workflow와 수집 예약 시각은 유지합니다. 저장소의 **Settings → Secrets and variables → Actions**에 Kaggle의 `KAGGLE_API_TOKEN`을 secret으로 등록하고, Kaggle 계정 이름이 `muyahoyeol`과 다르면 `KAGGLE_USERNAME` 변수를 추가하세요. 토큰 문자열은 로그나 코드에 넣지 않습니다.

음성은 Qwen3-TTS 1.7B CustomVoice를 사용합니다. 여성 Sohee에는 `config/briefing.yaml`의 아침 라디오 지시를 전달하고, 남성 Aiden에는 해당 여성 지시를 전달하지 않습니다. 모델 크기 때문에 실제 end-to-end 확인은 Kaggle T4에서 진행해야 합니다. 로컬의 짧은 샘플은 모델 설정과 대본 입력 확인용이며 전체 브리핑의 말투·발음 품질이나 2분 재생 목표를 보장하지 않습니다.

수집 직후 자동 실행은 저장소 변수 `ENABLE_KAGGLE_BRIEFING=true`로 켭니다. 기본값은 미설정(꺼짐)이며, 활성화에는 `KAGGLE_API_TOKEN` secret도 필요합니다. 수집 시작 시각보다 새로 생성된 스냅샷과 앱 기준일이 일치할 때만 GPU 실행을 시작합니다. 같은 날짜의 직전 자료와 날씨·공지·식단·일정이 모두 같으면 음성 생성을 건너뜁니다. 수집 시각과 오류 목록만 달라진 경우는 새 자료로 보지 않습니다. 부분 수집 오류는 허용하지만 오래된 자료, 날짜 불일치, 누락된 자료는 막습니다. 수동 GPU 실행은 `publish=true`가 기본값이며, 기본 브랜치에서만 게시합니다. 원래 수집 입력 해시가 GPU 입력과 같고 이미 게시된 음성보다 최신인 결과를 게시합니다. 수집 앱 날짜가 다음 날로 넘어가도 게시할 수 있습니다. 게시 job은 수집 writer와 직렬화하고 커밋 후 배포 workflow를 요청합니다.

Actions에서 workflow를 선택해 실행합니다. 날짜 입력을 비우면 한국 날짜를 사용하고, 날짜를 지정하면 그 날짜의 커밋된 `data/raw/YYYY-MM-DD/items.json` 스냅샷을 사용합니다. 결과에는 선택 날짜, GitHub run/commit, 입력·코드 bundle 해시, 커널 ID와 버전, NVIDIA T4 확인값이 포함됩니다. 작업은 비공개 Kaggle 커널을 만들고 최대 2시간 기다립니다. 이번 실행의 정확한 커널 버전에서 산출물을 가져와 날짜와 식별자, 파일 해시, 실제 MP3 재생 길이를 검증한 뒤 비공개 GitHub Actions artifact로 3일 보관합니다.

기본 수동 실행은 저장된 수집 자료로 음성을 만들고 검증 후 앱에 저장하고 배포를 요청합니다. 시험 실행은 `publish=false`로 게시를 끌 수 있습니다. 학교 자료를 새로 수집하지는 않습니다. Kaggle API token이 등록되지 않았거나 Kaggle이 T4를 제공하지 않으면 실행이 실패합니다. 취소되거나 커널이 강제 종료되면 Kaggle이 출력 파일을 제공하지 않을 수 있으며, 그 경우 진단 artifact도 남는다고 보장할 수 없습니다. 로컬 토큰은 `.env`에 두고 커밋하지 않습니다.

첫 GPU 실행은 전역 패키지 설치가 Torch 2.6과 사전 설치된 torchvision을 어긋나게 해 `torchvision::nms` import 오류로 실패했습니다. 패키지를 `/tmp/knu-audio-runtime/venv`에 격리한 재실행은 NVIDIA Tesla T4에서 end-to-end 검증됐습니다. 2026-10-05 수집 스냅샷의 날짜는 그대로 유지했습니다. 검증된 앱 파일은 `output/app/data/briefing/`에 있으며, 원본은 14개 구간과 10개 음성 파일, 앱 출력은 채널 음성을 합쳐 11개 구간과 6개 음성 파일입니다. 실행 기록과 복사된 파일별 해시는 `data/runs/briefing-kaggle-20261005.json`에 있습니다. 준비는 약 8분, 생성은 1,363.93초(대본 152.65초, 음성 1,211.28초), 커널 전체는 1,848.262초였습니다.

자동 게시 경로는 오프라인 검사만 완료됐으며 실제 GitHub 커밋·Pages 배포는 실행하지 않았습니다. 자동 실행 변수는 계속 꺼져 있습니다.

재수집 대상이 없어 이번 실행에서 새 입력을 만들지 않았으면 음성 생성은 정상적으로 건너뜁니다. 날짜 불일치, 읽기 실패나 깨진 JSON은 오류로 표시합니다.

음성 생성의 총 15,000자 제한은 제거했다. 실제 생성 문자 수는 실행 보고서의 `new_characters`에 계속 기록한다. 모델 응답 오류와 비어 있는 대본, 음성 생성 오류는 실패 처리한다. 재생성 대본에는 잘못된 숫자나 개인정보가 남아 있어도 규칙으로 다시 차단하지 않는다.

GitHub 생성 작업이 대기 제한 등으로 실패·중단되면 `완료된 Kaggle 음성 자동 게시`가 마지막 커널을 별도로 기다립니다. 전체 완료 결과만 검증·게시하며, 원래 실행에서 게시를 끈 경우는 자동 복구하지 않습니다. 원래 실행 ID로 완료 결과를 수동 게시할 수도 있습니다.

## 보조 Kaggle 계정

기본 계정의 주간 GPU 한도가 모자랄 때 팀원의 계정으로 실행할 수 있다. 등록하지 않으면 기본 계정만 쓴다.

- 저장소 Secret `KAGGLE_API_TOKEN_2`와 변수 `KAGGLE_USERNAME_2`에 보조 계정의 토큰과 사용자 이름을 등록한다. 계정 주인이 직접 등록하고, 저장소 관리자가 워크플로로 그 계정을 쓸 수 있게 된다는 점에 동의해야 한다.
- 음성 모델은 기본 계정의 비공개 데이터셋 하나를 함께 쓴다. Kaggle에서 그 데이터셋의 Sharing에 보조 계정을 추가해 둔다. 보조 계정이 데이터셋을 읽지 못하면 보조 계정을 고르지 않는다.
- 실행을 시작할 때 `kaggle quota`로 두 계정의 남은 GPU 시간을 확인한다. 기본 계정이 변수 `KAGGLE_MIN_GPU_HOURS`(기본 3시간) 이상이면 기본 계정을, 아니면 더 많이 남은 계정을 쓴다.
- 고른 계정은 그 실행이 끝날 때까지 쓴다. 묶음 이어가기는 같은 계정의 이전 커널을 입력으로 연결하므로, `resume_kernel`을 주거나 같은 실행을 다시 시도하면 이전 묶음이 있는 계정을 그대로 쓴다.
- 완료 결과 자동 게시와 취소 시 커널 삭제는 실행을 시작한 계정의 토큰을 쓴다.
- 한도를 넘기려고 여러 계정을 돌려 쓰는 것이 Kaggle 약관에 맞는지는 저장소에서 보증하지 않는다. 사용 전에 약관을 확인한다.

## 음성 모델을 Kaggle에 미리 저장

음성 작업은 비공개 데이터셋 `muyahoyeol/knu-audio-qwen3-tts-17b-0c0e3051`을 입력으로 연결한다. 공식 `Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice`의 revision `0c0e3051f131929182e2c023b9537f8b1c68adfe`를 그대로 저장하며 모델·토크나이저는 약 4.52GB이다. 모델 카드와 Apache-2.0 LICENSE도 포함한다. 학교 자료나 API 토큰은 넣지 않는다. 가중치 파일은 GitHub에 커밋하지 않는다.

Worker가 `/kaggle/input`에서 해당 모델을 찾고 TTS가 파일 해시를 확인한 뒤 읽기 전용 입력 폴더에서 직접 읽는다. Hugging Face에서 반복 다운로드하거나 임시 폴더로 큰 파일을 복사하지 않는다. 모델 연결 누락·다른 버전·파일 손상은 오류로 남긴다. 로컬에서 별도 모델 경로를 지정하지 않은 경우 기존 Hugging Face 캐시/다운로드 경로는 유지한다.

GPU에 모델을 올리는 시간과 음성을 생성하는 시간, 패키지 설치 시간은 계속 필요하다. 이 변경은 반복 모델 다운로드를 없애는 것이며 전체 속도의 실제 효과는 다음 GPU 실행에서 측정한다. 모델 버전을 바꿀 때는 새 이름의 비공개 데이터셋을 만들고 revision과 검증 목록의 해시를 함께 갱신한다. 현재 데이터셋은 같은 이름으로 덮어쓰지 않는다.

2026-10-09 비공개 데이터셋 version 1 등록 및 인터넷·GPU를 끈 Kaggle 확인 작업이 성공했다. 13개 파일 약 4.52GB를 해시 검증했고 검증 자체는 20.13초였다. 작업 시작 대기와 입력 연결 준비 시간은 이 수치에 포함하지 않는다. 실제 GPU 적재·음성 생성 및 전체 시간 비교는 아직 하지 않았다. 결과는 `data/runs/tts-model-cache-2026-10-09.json`에 남겼다.
