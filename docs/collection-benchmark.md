# 세 학과 전체 적재와 요청량 비교

2026-10-01 실측. 담당 범위는 수집기·파일 DB·브리핑 입력 파일이다.

## 최종 저장 확인

| 학과 | 목록 페이지 | 고유 공지 | 최종 저장 | 미저장 |
|---|---:|---:|---:|---:|
| 국어국문학과 학사공지 | 31 | 305 | 305 | 0 |
| 영어영문학과 학부공지 | 122 | 1,217 | 1,217 | 0 |
| 수학과 공지사항 | 281 | 2,808 | 2,808 | 0 |
| 합계 | 434 | 4,330 | 4,330 | 0 |

첫 전체 순회에서 확인한 글 ID 집합과 최종 DB ID 집합이 일치함을 검증했다. 실제 게시일 범위는 2011-03-17~2026-09-30이다. 미저장 0은 이 세 채널에서 확인한 ID 기준이며 경북대 전체 게시판을 수집했다는 뜻이 아니다. 삭제·비공개 글이나 목록이 이동하는 중의 일관성까지 보장하지 않는다.

텍스트 본문 3,954개, 이미지 전용 246개, 첨부 전용 128개, 정상 빈 본문 2개다. 이미지·첨부 내용은 읽지 않았고 본문 대신 null과 상태를 보존한다. 따라서 4,330개 모두 텍스트 본문을 추출했다는 의미는 아니다.

## 실제 요청량

| 학과 | 최초 전체 적재 요청 | 재실행 요청 | 재실행 상세 성공 | 재실행 상세 생략 |
|---|---:|---:|---:|---:|
| 국문 | 325 | 47 | 16 | 289 |
| 영문 | 1,335 | 132 | 8 | 1,207 |
| 수학 | 3,546 | 547 | 262 | 2,542 |
| 합계 | 5,206 | 726 | 286 | 4,038 |

실제 HTTP 요청 시도는 **86.05% 감소**했다. 최초 전체 적재는 약 103.6분, 재실행은 약 18.9분이었다. 시간은 서버 응답·네트워크 상황에 영향을 받으므로 고정 실행 시간으로 간주하지 않는다. 최초 측정 전 첫 페이지 샘플 55개가 이미 DB에 있었으며 완전히 빈 DB에서 시작한 값과 다르다.

재실행에는 DNS 오류로 누락된 글 복구도 포함됐다. 재실행 후 별도 원문 비교에 12회(목록 6회·상세 6회)를 더 요청했다. 이 12회는 위 비교표의 726회에 포함하지 않았다.

변화가 없고 7일 재확인 대상이 추가되지 않는 다음 실행은 약 496회로 계산된다(목록 434회 + 기존 재확인 대상 상세 62회). 이는 실측이 아닌 추정이다. 새 글·수정·고정 상태 변화·오래된 글의 7일 주기 도래가 있으면 달라진다. 7일 주기에는 오래된 본문 요청이 다시 늘어난다.

## 실패와 보강 내역

- 최초: 영문 2개·수학 3개의 목록/상세 불일치, 수학 225개의 DNS 이름 해석 실패. 오류를 빈 데이터로 바꾸지 않았다.
- 재실행: DNS 실패 225개 중 224개를 저장했고, 나머지 1개는 제목 말줄임 차이로 드러났다. 요청 실패는 사라졌으나 제목 불일치 6개가 남았다.
- 원문 확인: 6개 모두 목록 제목이 `..`로 잘렸고 글 ID·게시일이 일치했다. 목록 접두부가 상세의 전체 제목과 맞는 경우만 인정하도록 공통 제목 비교 함수를 보강했다. 저장은 상세의 전체 제목을 사용한다. 실제 제목 변경·날짜 불일치는 계속 오류로 처리한다.
- 6개를 모두 저장해 총 4,330개가 됐다. DNS 실패 225개 전체도 최종적으로 복구됐다.
- 같은 비교 규칙을 재확인 대상 판단에도 적용해, 오래된 긴 제목을 매일 수정된 글로 오인하지 않게 했다. 회귀 원본은 `collector/tests/fixtures/knu-cms/mismatches/`에 보관했다.
- 확인한 12개 응답에는 ETag·Last-Modified가 없었다. 다른 게시판까지 부재를 단정하지 않으며 현재 조건부 요청 최적화는 구현하지 않았다.

원래 실패 보고서는 그대로 보존하고 복구 결과를 따로 기록했다. 테스트 54개 통과.

## 효율성에 대한 판단

HTML 파일끼리 비교하는 방식이 아니다. 최신 HTML에서 글 ID·원문 필드를 추출하고 DB ID 및 내용 해시를 비교한다. 저장 HTML은 파서 테스트용이다.

현재 정책은 목록 전체 순회 + 최근 30일/고정/확인된 마감 예정 본문 재확인 + 오래된 본문의 7일 재확인이다. 전체 과거 적재는 준비·벤치마크용이고 일일 전체 본문 재다운로드를 목표로 하지 않는다.

다음 개선 후보는 최근 목록 구간을 매일 확인하고 전체 목록·오래된 본문을 주기적으로 점검하는 방식이다. 목록만 434회인 현재 방식의 비용을 줄일 수 있다. 다만 오래된 날짜로 새로 게시된 글·오래된 글의 수정은 늦게 발견할 수 있으므로 정렬·고정 구조를 검증하고 누락/지연 조건을 합의한 뒤 적용한다. 목록의 잘린 제목 뒤쪽만 바뀐 경우도 목록만으로 알아낼 수 없으므로 주기적 상세 재확인이 필요하다.

공식 API나 공개 JSON/RSS가 있으면 접근 가능성과 제공 필드를 확인해 우선 검토한다. 현재 세 채널은 공식 API를 전제로 하지 않고 공개 HTML로 검증했다. 다음 전체 계획은 `docs/roadmap.md`를 참고한다.
