# 플레이어 계약 schema_version 2

`manifest.json`은 date, collected_at, generated_at, mode, voices, departments, channels, segments, skipped_notices, warnings, bgm을 제공합니다. skipped_notices는 검수 실패로 제외된 공지의 ID·제목·URL·채널만 담고, 오류 상세는 내부 보고서에 둡니다.
mode: `text-only`(SLM 대본 생성 완료, 음성 없음) 또는 `slm-melo`(음성 생성 완료).
voices: 현재 `kr: {name, ready}`. UI는 이를 읽어 목소리 목록을 만들며 남녀 이름을 하드코딩하지 않습니다.

각 segment는 id, kind, title, script, generation(`fixed` 또는 `slm`), channel_ids, audio를 갖습니다.
`audio.kr = {url, duration_sec}`이며 실제 MP3 파일이 존재해야 합니다. SLM 구간은 review 필드에 검사 버전과 모델 digest를 기록합니다. 원문 전문과 검수용 문장은 manifest에 넣지 않습니다.

공지 대본은 SLM이 제목과 본문을 짧게 요약합니다. 결정론적 검수는 비어있음/길이 경계, 원문에 없는 숫자값, 일부 이메일·전화번호·학번/주민번호·비속어 패턴만 확인합니다. 문장의 의미나 날짜·대상·장소 관계의 정확성을 보증하지 않습니다. 공지 검수 실패는 해당 공지만 제외하고 나머지 빌드는 계속하며, 모델 연결·비공지 검수·TTS 실패는 빌드를 실패 처리합니다. 모든 공지가 제외되어도 empty_notices와 outro는 유지합니다.

날씨는 예보 수치를 생활 조언으로 변환한 기준 문장을 사용한다. 기온·강수 확률은 음성으로 읽지 않으며, 낮은 기온의 겉옷·큰 일교차·비의 우산 안내를 유지한다. 산책 권유는 맑고 비 가능성이 낮으며 낮 최고가 온화한 일일 예보에서만 제공한다. 시간대별 예보가 없으므로 오후 피크닉을 보장하는 문장은 만들지 않는다.

순서: greeting → weather → notice(선택 학과/공지) → meal(선택 식당) → events → outro.
들려줄 공지가 없으면 "공지가 없다"는 안내 없이 다음 구간으로 넘어갑니다. 학식이 선택되지 않으면 empty_meals 구간을 사용합니다. 공통 notice도 사용자가 개별 제외할 수 있습니다. 날짜·D-day는 입력 자료 기준일 기준입니다.

BGM은 별도 audio 객체로 루프 재생하며 음성이 멈추면 일시정지합니다. MP3에 섞여 있는 파일은 아닙니다. 브라우저 자동재생 정책 때문에 사용자가 듣기 버튼을 눌러야 시작합니다.

## 한 편으로 듣기 (2026-10-04)

사용자가 내 브리핑 듣기를 누르면 선택 구간 MP3를 브라우저에서 디코딩하여 순서대로 하나의 WAV로 합칩니다. 진행 막대는 전체 길이를 표시하고 하나의 파일 안에서 탐색합니다. 음성 WAV 저장으로 같은 파일을 내려받을 수 있습니다. 다운로드는 음성만 포함하고 배경음악은 플레이어에서 별도로 재생합니다. 선택 변경 시 이전 합치기 작업을 취소하고 음성을 해제합니다. 브라우저 메모리 보호를 위해 15분까지 지원합니다. 모델을 다시 호출하지 않으며 서버는 기존 정적 MP3를 전달합니다.


## 이름 인사와 대본 미리보기 (2026-10-06)

새 음성 결과에는 공통 인사 MP3와 `personal_template`을 가진 `greeting` 구간이 추가된다. `intro`에는 날씨·확인된 학교 이벤트만 들어간다. 웹은 `greeting → intro → 선택 공지 → 선택 학식 → outro`로 재생한다. 이전 결과의 `intro`는 기존 방식으로 재생한다.

학생 이름은 브라우저에만 저장한다. 이름 인사는 기기의 한국어 `speechSynthesis`로 읽고, 본문은 Qwen3-TTS MP3를 재생한다. 기기 한국어 음성이 없거나 재생하지 못하면 이름 없는 공통 인사 MP3로 대체하며 안내를 표시한다. 기기별 목소리가 다를 수 있고 개인 이름을 Qwen 화자의 목소리로 생성하는 기능은 아니다.

인사와 생활 조언은 세 가지 말투를 지원하며 마무리는 “오늘도 좋은 하루 보내세요!”로 통일한다. 운영 생성은 날짜로 말투를 고르므로 같은 날 다시 생성해도 캐시를 재사용한다. 세 가지 미리보기는 순서를 무작위로 섞고, SLM temperature 0.55로 별도 생성한다. 게시판을 지정하지 않으면 공지 최대 두 개만 미리보기로 선택한다. 학생별 최종 재생목록이 아니다.

```bash
python -m briefing.samples --input data/raw/2026-10-06/items.json --name 김경민
# 특정 게시판만 미리보기
python -m briefing.samples --input data/raw/2026-10-06/items.json --name 김경민 --channel knu-academic
```

결과: `preview/morning-samples.json`과 `.md`. 미리보기는 공개 음성·운영 검수 파일을 덮어쓰지 않는다. 일부 공지가 검수 실패로 빠지면 상태가 `partial`이며, 해당 공지는 미리보기 script에서 제외된다. 변경된 대본을 실제 Qwen 음성으로 듣기 위해서는 기존 `briefing.build → briefing.app_export`를 다시 실행해야 한다. 코드만 배포하면 기존 MP3의 대본은 바뀌지 않는다.


## 앱 대본과 음성 동기화 (2026-10-07)

기기 음성은 `SpeechSynthesisUtterance.onstart`로 현재 말풍선을 바꾼다. 기다리는 시간이나 글자 수로 다음 문장으로 넘어가지 않는다. 일시정지 후 같은 문장부터 다시 읽으며, 취소된 음성의 늦은 콜백은 무시한다. 기기 음성 목록이 재생 도중 준비되더라도 현재 재생 방식과 표시 대본을 바꾸지 않는다. 기본 인사 MP3로 대체하면 학생 이름이 없는 대본을 표시한다.

앱 출력의 선택적 `cues`는 합치기 전 녹음별 대본과 시작·끝 초를 보존한다. 기존 MP3는 문장별 시각이 없으므로 한 녹음 전체를 한 말풍선으로 표시한다. 문장별 정렬을 제공하는 기능은 아니며, 긴 공지는 긴 말풍선으로 보일 수 있다. 시간표와 대본이 일치하지 않으면 전체 구간 표시로 돌아간다.

회귀 확인: `node collector/tests/test_briefing_chat_player.mjs`.

## 게시판 간 같은 공지의 공유

수집 DB와 `items.json`은 게시판별 원본을 그대로 보존한다. 중복 비교용 사본에서 제목의 `[안내]`, `[공지]`, `[공통]`, `[교직]`, `[대학원]`, `[학부]`, `[재안내]` 접두어와 장식 기호, 본문의 미리보기 UI 문구·붙임 목록·단순 인사·연락처 안내를 정리한다. `[필수]`는 의미를 보존한다. 저장 원문과 모델 입력은 바꾸지 않는다. 정리한 제목·본문·저장 마감일이 같으면 합친다. 제목·마감일이 같고, 본문의 숫자 순서·횟수와 대상·자격·장소·신청·일정·예정/확정·불가/제외 등을 포함한 보호 문장이 같으면 100자 이상 본문에 한해 양방향 문자열 유사도 90% 이상도 합친다. 보호 문장 비교는 규칙이므로 모든 의미 차이를 판별하지는 못한다. 본문 없는 글과 짧은 유사 문장은 서로 다른 ID끼리 합치지 않는다. 대표 글과 직접 비교하며 유사한 글을 연결해서 연쇄 병합하지 않는다.

내부 공지 segment의 `notice_refs`에는 모든 원문을 `{channel_id, postId, title, url, posted_at, deadline, reason}`으로 보존하고 `channel_ids`에는 관련 채널을 연결한다. 동일 그룹의 대본과 음성은 한 번만 만든다.

새 앱 출력의 공지 segment는 `kind: notice`와 고유 `id`, 관련 `channel_ids`, `notice_refs`를 제공한다. `channel_id`는 이 공지 구간의 ID이며 채널 선택에는 `channel_ids`를 사용한다. 카드의 `channel_id`와 `postId`로 해당 학과 원문을 연다. 여러 학과를 골라도 재생 목록은 segment ID당 한 번만 추가하고 카드에는 선택한 학과의 원문만 표시한다. 인사·날씨·식당·마무리와 이전 게시판 단위 출력은 기존 방식으로 지원한다. 기존 배포 음성은 자동으로 변경하지 않으며 다음 브리핑 생성부터 새 방식이 적용된다.
