# 게시 음성 14일 보관

`output/app/data/briefing/`의 MP3를 새 브리핑 게시 시 정리한다. Kaggle 정상 게시·복구 게시와 로컬 `briefing.app_export`에 같은 규칙을 적용한다.

- 기준은 새로 게시하는 브리핑 날짜다. 오늘을 포함한 최근 14일(기준일 ~ 기준일-13일)의 음성을 보관한다.
- 예: 10월 10일 결과 게시 시 9월 27일~10월 10일 사용한 음성을 보관하고, 9월 26일 이전 음성을 삭제한다.
- 같은 파일을 다시 사용하면 마지막 사용일이 갱신된다. 최신 `segments.json`이 사용하는 음성은 항상 보호한다.
- 사용 날짜는 `audio-retention.json`에 기록하며 새 음성·메타데이터를 검증하고 교체한 뒤 정리한다. 게시 검증 실패·오래된 결과 게시 거부 시에는 정리하지 않는다.
- 최초 적용 시 기존 `data/runs/briefing-kaggle-*.json`의 검증된 게시 기록과 직전 `segments.json`에서 날짜를 복원한다. 날짜 기록이 없는 파일은 최초 적용일로부터 14일 보관하는 유예를 둔다.
- 브리핑 게시가 없으면 별도 정리 작업도 실행하지 않는다. 다음 성공 게시 때 정리한다.

MP3만 정리한다. 공지 DB, 수집 원문, 실행 기록, 대본 메타데이터, BGM, 생성 캐시는 이 작업에서 삭제하지 않는다. Git 과거 이력에 남은 파일까지 지우는 작업도 포함하지 않는다. 최신 체크아웃과 이후 홈페이지 배포의 파일 수를 줄이는 변경이다.

14일 이전의 파일을 참조하는 오래 열어 둔 화면은 재생에 실패할 수 있다. 새로고침하면 최신 브리핑을 읽는다. 음성 품질과 생성 방식은 바꾸지 않는다.
