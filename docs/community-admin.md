# 신고와 관리자 화면

일반 이용자는 공유 모집글 상세에서 **이 글 신고하기**를 눌러 1~300자로 사유를 남긴다. 개인정보를 적지 않는다. 같은 브라우저가 같은 글을 다시 신고하면 기존 신고를 유지한다. 신고만으로 자동 숨김 처리하지 않는다.

관리자는 모임 서버의 `/admin`에서 로그인한다. 위에는 고정 멘트 편집과 신고된 글, 아래에는 전체 게시물이 표시된다. 제목 검색과 30개씩 더 보기를 지원하며 신고되지 않은 글도 숨김·해제·삭제할 수 있다. 삭제 확인 후 글·신청 내역·신고가 함께 영구 삭제되며 되돌릴 수 없다. 현재 주소는 https://knua-community-api.knua-public-pr73.workers.dev/admin 이다. 홈페이지의 `/KNU-AUDIO-public/admin/`는 이 로그인 화면으로 이동하는 입구다. 로그인 화면은 누구나 열 수 있지만 신고 자료와 숨김 기능은 관리자만 사용할 수 있다.

숨긴 글은 일반 목록·상세·신청·알림에서 제외된다. 작성자의 내 모집글에서는 확인·수정·삭제할 수 있으나 수정해도 숨김은 풀리지 않는다. 숨김은 기존 신청이나 글을 삭제하지 않는다. 브라우저 권한 복구는 이번 작업에 포함하지 않는다.

## 팀원이 서버에 적용할 순서

관리자·신고 기능의 최초 설치에는 **0003_moderation.sql**, 고정 멘트 편집에는 **0004_fixed_message.sql**이 필요하다. 기존 서버 업데이트는 아래의 고정 멘트 항목을 따르고 관리자 계정을 다시 등록하지 않는다.

1. 기존 Worker/D1에 연결된 실제 설정 파일을 사용한다. 새 데이터베이스를 만들지 않는다.
2. 먼저 데이터베이스 변경을 적용한다.
   ```sh
   npx wrangler@4 d1 migrations apply knua-community --remote --config community/wrangler.local.toml
   ```
3. Worker를 배포한다.
   ```sh
   npx wrangler@4 deploy --config community/wrangler.local.toml
   ```
4. 관리자가 자신의 터미널에서 계정을 정하고 등록한다. 비밀번호는 입력할 때 화면에 표시되지 않으며 파일에 저장하지 않는다.
   ```sh
   python community/admin_credentials.py --config community/wrangler.local.toml
   ```
5. 홈페이지 배포 후 실제 글 1개를 신고하여 관리자 숨김·해제와 일반 목록 반영을 확인한다.

설정 파일 이름이 다르면 실제 파일 경로로 바꾼다. `community/setup.py`는 옛 Pages 연결용으로 이 Worker 배포에 사용하지 않는다. 현재 D1 이름이 예시와 다르면 실제 이름을 사용한다. 새 관리자 계정은 `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH` Worker Secrets로 등록한다. 평문 비밀번호를 GitHub나 채팅에 올리지 않는다.

비밀번호는 PBKDF2-SHA256(210,000회, 무작위 salt)로 해시 처리한다. 로그인 쿠키는 HTTPS·HttpOnly·SameSite=Strict이며 8시간 뒤 만료된다. 로그아웃 또는 계정 변경으로 기존 세션을 무효화한다. 로그인은 IP별 시간당 10회, 서버 전체 시간당 200회 제한한다. 관리자 변경 요청은 같은 서버 출처에서만 받는다. 신고 사유는 일반 이용자에게 공개하지 않는다.

## 고정 멘트 편집

- 기존 관리자 계정으로 로그인하고 상단 **고정 멘트** 칸에서 1~500자로 입력한 뒤 저장한다.
- 저장은 즉시 완료되지만 음성은 다음 정기 생성·배포가 완료되면 바뀐다. 저장만으로 Kaggle 실행을 시작하지 않는다.
- 이후 생성에서도 저장한 문장을 유지한다. 문장이 그대로면 기존 음성 캐시를 사용한다. 공지 없음 안내는 이 편집 대상이 아니다.
- 다른 관리 화면에서 먼저 수정했다면 덮어쓰지 않고 새로고침을 안내한다.
- 생성 시작 때 문장을 읽어 해당 실행에 고정한다. 생성 도중 수정한 문장은 그다음 실행에 반영된다.
- 서버 일시 장애는 실행 기록에 경고를 남기고 마지막 게시 멘트를 유지한다.
- 방송 문장만 `/api/community/fixed-message`에서 공개 조회한다. 저장·변경은 관리자 인증이 필요하다. 비밀번호·개인정보를 멘트에 적지 않는다.

### 기존 서버 업데이트

기존 운영 서버 소유 계정에서 **0004_fixed_message.sql** 마이그레이션을 적용한 뒤 Worker를 배포한다. 기존 데이터베이스와 관리자 계정은 그대로 사용한다. 위의 `d1 migrations apply`와 `deploy` 명령을 운영 설정 파일로 실행한다. 새 토큰·새 관리자 비밀번호 등록은 필요 없다.

서버 배포 후 관리자 저장→로그아웃→다시 로그인하여 유지되는지 확인하고, 공개 조회에 같은 문장이 반환되는지 확인한다. 다음 정기 음성 생성 후 홈페이지 대본의 **크누아의 응원**이 저장한 문장과 같은지 확인한다.
