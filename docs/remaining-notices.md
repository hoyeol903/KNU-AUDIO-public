# 남은 필수 게시판 6개

2026-10-01. 생명공학부·의학과·인공지능계열·중어중문학과·치의학과·컴퓨터학부의 대표 공지 게시판을 수집기에 추가했다. 기존 수집기의 중복 제거·변경 확인·부분 실패·원자적 저장을 그대로 쓴다.

DB 전체는 **4,879개**다. 각 게시판의 이번 확인 범위에 나온 모든 글 ID가 DB에 있는지, 두 공유 채널이 함께 연결됐는지 대조했다. 운영 시작 기준도 5개 게시판 모두 저장돼 있다. 의대는 최초 제목 표시 차이로 28건 실패했지만 수정 후 모두 저장했다. 최초 실패 보고서를 남기고 최종 결과는 `data/runs/remaining-notices-20261001.json`에 따로 저장했다. 첫 적재 자료를 오늘 새 공지로 잘못 내보내지 않도록 신규 후보는 0개로 둔다.

주소가 있고 수집을 허용한 대표 필수 채널 **139개(고유 게시판 136개)**는 모두 선택 가능한 상태다. 이 숫자는 모든 학과의 모든 게시판·모든 과거 글을 저장했다는 뜻이 아니다. CMS의 빈 게시판 2곳은 목록만 검증했고, 주소 미확인 조직 4곳은 별도 검토 대상으로 유지한다.

## 확인한 범위

6개 채널 모두 공개 목록·대표 상세·2페이지를 확인했다. 인공지능계열과 컴퓨터학부는 두 목록의 ID·제목·날짜·고정 여부와 대표 상세 본문이 일치하여 같은 게시판으로 묶었다. 따라서 6개 채널을 선택하면 실제 요청하는 게시판은 5개다.

의대는 `.board-list`, `.board-view`와 `mv_data` 구분자 `||`를 사용하는 `med-cms`로 분류했다. 그누보드는 표형(생명공학부·인공지능·컴퓨터)과 카드형(중어중문학과)을 지원한다. 중어중문학과에는 현재 글이 있으므로 예전 빈 게시판 메모는 지웠다. 사용자 메모와 공지 대상 확인 메모는 유지했다.

## 실행

프로젝트 루트에서 아래 명령으로 이 6개 채널만 확인한다. 현재 로컬에서는 python 대신 `/opt/anaconda3/bin/python3`를 쓴다.

```bash
python -m collector.run \
  --channel-id notice-b1133d4c8b3b \
  --channel-id notice-a363da417a07 \
  --channel-id notice-b34ee1a00417 \
  --channel-id notice-6b04da14aae1 \
  --channel-id notice-7414782e7dbb \
  --channel-id notice-fefffa32e24c

python -m pytest -q
python docs/check_channels.py
```

새 게시판을 최근 구간부터 처음 시작할 때만 `--mode start`를 붙인다. 이미 운영을 시작한 게시판은 daily를 쓴다. `--required-knu-cms`는 여전히 CMS 전용이며 이 6개를 포함하지 않는다. 인자 없는 기본 실행도 기존 5개(학교·전자·국문·영문·수학)를 유지한다.

## 제한

- 최근 구간 운영 시작은 모든 과거 글을 저장했다는 뜻이 아니다. 목록은 최근 30일과 오래된 일반 글 페이지 2개까지 읽는다. 고정글·마감 예정·검토 필요 글은 기존 정책으로 확인한다. 이 범위 밖 과거 일반 글은 자동 수집으로 보장되지 않으며 필요할 때 수동 `--mode full`로 확인한다.
- 현재 카탈로그의 대표 필수 게시판만 지원한다. 학과의 모든 선택 게시판을 지원한다고 가정하지 않는다. 주소가 없는 조직 4개는 검토 목록에 유지했다.
- 이미지 글의 OCR·첨부 파일 내용·자동 마감일 추출·예약 실행은 아직 없다. 본문을 읽지 못한 상태를 빈 공지로 숨기지 않는다.
- 상세의 2자리 연도는 목록의 4자리 날짜와 대조한다. 년도를 임의로 채우지 않으며 목록과 날짜가 다르면 저장을 보류하고 오류를 기록한다.
- fixture는 `collector/tests/fixtures/remaining/`, 대표 검증 근거는 `data/remaining-validation.json`, 최종 실행 결과는 `data/runs/remaining-notices-20261001.json`에 있다.
