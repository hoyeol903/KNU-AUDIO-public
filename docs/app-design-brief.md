# 크누아 앱 화면 디자인 의뢰서

2026-10-03 기준. 디자인을 맡는 사람이나 AI 도구에 이 문서 하나만 넘기면 되도록 썼다. 개수와 글자 길이는 2026-10-02 저장 자료에서 셌고, 예시 문구는 10-01~10-02 실제 자료에서 가져왔다. "추정"이라고 적은 값만 어림값이다.

## 1. 무엇을 디자인하나

**크누아(KNU AUDIO)**는 경북대 신입생이 아침 등굣길에 이어폰을 끼고 재생 버튼 한 번으로 "오늘 학교에서 알아야 할 것"을 1~2분 동안 듣는 서비스다. 듣고 난 뒤에는 방금 들은 공지를 화면에서 다시 확인하고 원문으로 넘어간다.

디자인할 것은 휴대폰 웹 화면 6개다. 설치형 앱이 아니라 브라우저에서 여는 웹 페이지지만 앱처럼 보여야 한다.

지금 동작하는 시험 화면이 있다. 기능과 정보는 이 화면이 기준이고, 모양은 전부 새로 잡아도 된다.

```bash
python -m collector.export_app
python -m http.server 8000 --directory output/app
```

브라우저에서 http://127.0.0.1:8000 을 연다. 화면 원본은 `tools/app-test.html`이다.

## 2. 사용자와 사용 상황

- 경북대 2027학년도 신입생. 학교 게시판이 어디 있는지, 무엇을 봐야 하는지 아직 모른다.
- 아침 등굣길에 걷거나 버스에서 한 손으로 쓴다. 화면을 오래 보지 않는다.
- 하루에 한 번, 1~2분 쓴다. 머무는 앱이 아니라 듣고 닫는 앱이다.
- 회원가입과 로그인이 없다. 이름과 학과는 그 브라우저에만 저장된다.

## 3. 동작 원리

화면은 아래 순서로 만들어진 자료를 보여주기만 한다. 화면에서 새로 계산하거나 학교 사이트를 부르지 않는다.

1. 매일 새벽 수집기가 학교·학과 게시판을 돌며 새 글을 저장한다.
2. 저장한 글 가운데 "오늘 알릴 글"만 고른다. 조건은 두 가지뿐이다.
   - **새 글**: 오늘 처음 발견했고 올린 지 30일이 안 된 글
   - **마감 알림**: 마감이 3일 뒤, 1일 뒤, 오늘인 글
3. 날씨, 학식, 학사일정을 함께 가져온다.
4. 이 자료로 음성 브리핑을 만든다(다른 팀원 담당, 아직 미구현).
5. 화면은 사용자가 고른 게시판에 해당하는 것만 걸러서 보여준다.

사용자가 고르는 것은 학과 하나와 선택 항목뿐이다.

- **필수 게시판**: 학과를 고르면 자동으로 정해진다. 끌 수 없다. 대부분 3개다(학교 학사공지 + 단과대학 게시판 + 학과 공지).
- **선택 항목**: 다른 학과의 공지(복수전공·관심 학과용)와 식당. 직접 켜고 끈다.

자료는 하루에 한 번만 바뀐다. 그래서 화면에 "자료 기준일"이 있고, 기준일이 오늘이 아니면 "오늘" 대신 "기준일"이라고 표시한다.

## 4. 화면별 내용

각 화면에 들어가는 정보와 실제 예시다. 배치와 표현은 자유다.

### 4-1. 시작

처음 한 번만 본다.

| 요소 | 내용 |
| --- | --- |
| 이름 입력 | 최대 20자. 홈 인사말에 쓴다 |
| 학과 검색 | 164개 학과, 24개 단과대학. 글자를 치면 목록이 줄어든다 |
| 학과 목록 항목 | 학과 이름 + 단과대학 이름. 예: 전자공학부 / IT대학 |
| 다음 버튼 | 이름과 학과를 모두 채워야 눌린다 |

가장 긴 학과 표기는 "첨단기술융합대학 · 첨단기술융합대학 자율학부1"이다. 같은 이름의 학과가 있어서 단과대학 이름을 반드시 함께 보여줘야 한다.

### 4-2. 게시판 고르기

시작 직후, 그리고 홈의 설정에서 다시 들어온다.

| 요소 | 내용 |
| --- | --- |
| 필수 목록 | 자동 포함된 게시판. 끌 수 없음을 알 수 있어야 한다. 예: 학교 학사공지, IT대학 · 게시판, 전자공학부 · 공지사항 |
| 다른 학과 공지 | 163개 학과 중 여러 개 선택. 검색 가능. 항목마다 "필수 공지 N개" 표시 |
| 식당 | 현재 2곳: GP감꽃 식당, 정보센터 식당 |
| 완료 버튼 | 선택한 게시판 총 개수를 함께 보여준다. 처음엔 "시작하기", 설정에서는 "저장" |

매일 여는 화면이다. **재생이 주인공**이고 나머지는 그 아래에 온다.

| 요소 | 내용 | 예시 |
| --- | --- | --- |
| 인사 | 이름 | 호열님, 안녕하세요 |
| 자료 기준 | 날짜, 확인 시각, 내 학과 | 2026-10-02 · 15:42 · IT대학 · 전자공학부 |
| 브리핑 재생 | 5장 참고. 아직 미구현 | 1분 48초 |
| 날씨 | 요약, 최저·최고 기온, 비 올 확률 | 부분적으로 흐림 · 14.1° / 21.3° · 45% |
| 오늘 숫자 | 새 글 수, 마감 알림 수, 학사일정 수 | 2 · 0 · 1 |
| 학사일정 | 제목, 기간, 남은 일수 또는 "진행 중" | 심사용 논문 접수 · 9.30~10.2 · 진행 중 |
| 내 게시판 목록 | 이름, 저장된 글 수, 오늘 소식 수, 필수/선택 | 전자공학부 · 공지사항 · 150개 · 오늘 1 · 필수 |
| 확인할 내용 | 못 읽은 자료 목록. 평소엔 접혀 있다 | 오늘 날씨를 수집하지 않았습니다 |

## 5. 브리핑 재생

서비스의 핵심이지만 음성은 아직 만들어지지 않았다. 형식만 정해져 있으니 이 형식에 맞춰 디자인한다.

브리핑은 한 덩어리가 아니라 **구간 여러 개**로 이루어진다. 사람마다 고른 게시판이 달라서 구간 조합도 다르다.

- 처음: 인사와 날씨 (모두 공통)
- 가운데: 내 게시판별 구간. 오늘 소식이 있는 게시판만 구간이 생긴다
- 끝: 마무리 한마디 (모두 공통)

구간 하나가 가진 정보는 다음과 같다.

| 정보 | 설명 |
| --- | --- |
| 구간 제목 | 예: 전자공학부 소식 |
| 음성과 길이 | 초 단위 |
| 대본 | 읽어주는 글 전문 |
| 요약 카드 | 그 구간에서 말한 항목들. 종류는 날씨 / 마감 임박 / 학식 / 소식 넷 중 하나. 제목, 설명, 원문 링크, 남은 일수 |

전체 길이는 1분 30초~2분이 목표다.

디자인에서 정해줘야 할 것은 다음과 같다.

- 재생 버튼 하나로 처음부터 끝까지 이어 듣는 흐름
- 지금 어느 구간을 듣는 중인지, 전체 중 어디쯤인지
- 구간 건너뛰기와 다시 듣기
- 듣는 중에 그 구간의 요약 카드가 보이고, 카드에서 원문으로 넘어가는 길
- 대본을 글로 읽고 싶은 사람을 위한 보기
- 화면을 끄거나 다른 앱으로 가도 재생이 이어지는 상황

## 6. 꼭 그려야 하는 상태

평소 화면만 그리면 실제로는 대부분의 날에 어색해진다. 아래 상태를 각각 그린다.

- **소식 없는 날**: 가장 흔한 날이다. 137개 게시판 전체에서 하루 새 글이 6개였다. 내 게시판 3개에는 0개인 날이 더 많다. 이날에도 날씨와 학식 브리핑은 있다. 비어 보이지 않게 한다.
- **소식 많은 날**: 새 글 5개 이상과 마감 알림이 겹친 날.
- **날씨·학식·일정을 못 가져온 날**: 해당 영역에 "오늘 자료를 가져오지 못했습니다"를 보여준다. 영역을 통째로 숨기지 않는다.
- **본문을 못 읽은 글**: 전체 글의 약 10%는 본문이 이미지나 첨부파일뿐이라 글자가 없다. "원문에서 확인하세요" 안내와 원문 버튼을 앞세운다.
- **마감일 없는 글**: 대부분의 글이다. 마감 표시를 비워둔다.
- **아직 수집하지 않은 게시판**: "저장된 공지 없음".
- **자료가 어제 것일 때**: "오늘" 대신 "기준일"로 표기가 바뀐다.
- **불러오는 중, 불러오기 실패**: 실패 화면에는 다시 시도 버튼.
- **브리핑이 아직 없는 날**: 재생 영역이 비활성으로 보이되 아래 글 목록은 쓸 수 있다.

## 7. 글자 길이와 개수

| 항목 | 보통 | 최대 |
| --- | --- | --- |
| 글 제목 | 33자 | 110자 |
| 게시판 이름 | 12자 안팎(추정) | 22자 |
| 내 게시판 수 | 3~5개 | 다른 학과를 많이 고르면 20개 이상 |
| 게시판 하나의 저장 글 | 수십~수백 개 | 2,811개 (화면에는 30개만) |
| 하루 새 글 (내 게시판 기준) | 0~2개(추정) | 10개 안팎(추정) |
| 본문 | 수백 자(추정) | 수천 자(추정) |

가장 긴 제목 예시: "[진로취업과] '26 하반기 캠퍼스 리크루팅 안내(두산에너빌리티, 대우건설, 외투기업(10개사), 팜스코, 써드브릿지, 파네시아, 한미그룹, 일본IT기업(네조트,TMES,NCD테크놀리지), 국정원)"

실제 제목에는 ★, 【】, [공통] 같은 기호와 머리말이 자주 붙는다. 제목은 원문 그대로 보여주고 고치지 않는다.

## 8. 지켜야 할 것과 자유로운 것

지켜야 할 것

- 휴대폰 세로 화면 기준(가로 360~430). 넓은 화면에서는 가운데 정렬.
- 밝은 화면과 어두운 화면 둘 다.
- 누르는 영역은 44 이상, 글자와 배경 대비는 읽기 기준(4.5:1) 이상.
- 날짜, 마감일, 제목, 메뉴는 원문 값 그대로. 꾸미려고 줄이거나 바꾸지 않는다.
- "자료가 없다"와 "가져오지 못했다"를 다르게 보여준다.
- 모든 공지에서 학교 원문으로 가는 길이 있어야 한다.
- 필수 게시판은 끌 수 없다.

지금 자료로는 만들 수 없으니 넣지 않는 것

- 로그인, 회원 정보
- 푸시 알림
- 글 전체 검색, 즐겨찾기, 읽음 표시, 댓글
- 본문 속 이미지와 첨부파일 보기
- 지난 날짜 브리핑 다시 듣기 (형식 미정)

자유로운 것

- 색, 글꼴, 아이콘, 분위기 전부. 시험 화면의 빨간색은 임시다.
- 화면 구성과 이동 방식. 탭, 카드, 목록 등.
- 홈에서 무엇을 위에 둘지. 단 재생이 첫 화면에서 바로 보여야 한다.

확인이 필요한 것

- 경북대 공식 로고와 상징물은 사용 허락을 확인하기 전에는 쓰지 않는다.

## 9. 받고 싶은 결과물

1. 화면 6개(4장)와 브리핑 재생(5장)의 시안. 밝은 화면과 어두운 화면.
2. 6장의 상태별 화면.
3. 색·글자 크기·간격·모서리 값 목록.
4. 반복해서 쓰는 부품 목록(버튼, 목록 항목, 표시 딱지, 카드, 재생 막대 등).

## 10. AI 디자인 도구에 넣을 때

이 문서 전체를 붙여 넣고 아래 문장을 덧붙인다.

```text
위 의뢰서대로 크누아의 휴대폰 웹 화면을 디자인해줘.

- 먼저 홈 화면을 서로 다른 방향 3가지로 보여줘. 셋 다 "소식 없는 날"과 "소식 많은 날"을 함께 그려서 비교할 수 있게 해줘.
- 내가 하나를 고르면 그 방향으로 나머지 화면과 6장의 상태를 모두 만들어줘.
- 예시 글자는 의뢰서에 있는 실제 값을 써. 지어낸 공지 제목이나 "Lorem ipsum"은 쓰지 마.
- 의뢰서 8장의 "넣지 않는 것"에 있는 기능은 그리지 마.
- 마지막에 색·글자 크기·간격 값을 표로 정리해줘.
```
