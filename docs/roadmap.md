# 수집기·파일 DB 다음 작업 계획

2026-10-01 사용자 확인: **우리 담당은 collector와 파일 기반 DB만**이다. 대본 생성·사실 검증·TTS·웹 플레이어는 다른 담당 영역이다. 기존 제품 전체 구상과 우리 구현 범위를 구분한다. DB 서버를 추가하지 않고 `collector/store.py`를 통해 저장소의 JSON을 읽고 쓴다.

## 우선순위

- 학교 공통 학사공지(knu-wbbs)와 전자공학부(gt-board)는 추가했다. 그누보드·의대·치대 등 남은 필수 6개도 추가했다. 명시된 마감일 추출까지 추가했다. 공지 신규·마감 알림과 items.json 전달을 추가했다. 대구 날씨·생협 두 식당·학사일정도 실제 수집했다. 수동 공지는 필요할 때 추가하며 다음은 선택 출처 보강·일일 운영 점검과 저장소 이전 후 새벽 자동 실행이다. KNU CMS 확대 결과와 아직 확인할 조건은 docs/knu-cms-expansion.md를 읽는다. 새 채널 전체 과거 적재는 완료되지 않았다. 검증된 소수 필수 채널의 입력 파일까지 완성한 뒤 확대한다.
- 모든 학과의 모든 과거 글 전체 적재를 MVP 선행 조건으로 삼지 않는다. 초기 적재 비용과 일일 요청량을 분리해 실제 필요한 이력 범위를 정한다.
- 5번 마감 추출은 확실한 원문부터 진행하며, 미확인은 null로 전달한다. 추측한 마감 알림은 만들지 않는다.
- 우리가 제공할 최종 연결 지점은 `data/raw/<날짜>/items.json`, 공지 DB, 채널 설정과 계약/운영 문서다. 브리핑 담당이 이 입력을 소비한다.
- 새 의존성, API 키, 데이터 계약 변경, 요청 간격·재시도 규칙은 CLAUDE.md와 docs/contracts.md를 따른다.
