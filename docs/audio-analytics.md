# 음성 이용 통계 — Google Analytics

기존 Google Analytics 속성(G-RLJ8SEF3JF)에 아래 3개 이벤트만 추가한다. 별도 통계 서버나 새 라이브러리는 필요 없다.

| 이벤트 이름 | 의미 |
|---|---|
| briefing_start | 음성 파일 또는 기기 TTS가 실제로 재생되기 시작함. 한 번의 듣기에서 첫 시작만 기록 |
| briefing_complete | 구간 이동이나 음성 오류 없이 마지막 구간까지 재생됨 |
| briefing_pause | 재생 중 일시정지, 이어폰·기기의 정지, 또는 재생 중 페이지를 떠남 |

일시정지 후 이어 듣는 것은 새 시작으로 집계하지 않는다. 다시 일시정지하면 멈춤 횟수는 늘어난다. 끝까지 들은 뒤 처음부터 다시 듣거나 선택 설정을 바꾸어 새 듣기를 시작하면 새 시작으로 기록한다. 자동 구간 전환은 새 시작·일시정지로 기록하지 않는다. 소리를 재생하지 않고 시간만 흘러가는 화면은 시작으로 기록하지 않는다.

이벤트에는 이름, 학과, 식당, 게시판, 공지 제목·본문, 음성 URL, 사용자 입력이나 별도 식별자를 넣지 않는다. 기존 GA의 쿠키·방문 정보 처리는 그대로이며 개인정보 안내에도 음성 이용 기록을 추가했다. localhost, 127.0.0.1, 파일로 연 테스트의 음성 이벤트는 전송하지 않는다.

## 어디서 보나

Google Analytics의 **보고서 → 실시간**에서 이벤트 이름을 확인한다. 누적 통계는 이벤트 보고서에서 기간을 정하고 위 이름을 확인한다. 화면 메뉴 이름은 계정의 보고서 구성에 따라 다를 수 있다. 이벤트 수는 행동 횟수이고 사용자 수는 GA가 구분한 이용자 수다. 별도 맞춤 매개변수 등록은 필요 없다.

시작과 완료를 같은 기간으로 비교하면 얼마나 끝까지 듣는지 참고할 수 있다. 다만 일시정지 후 다시 듣는 이용자가 있으므로 멈춤 수를 곧바로 이탈자 수로 해석하지 않는다. 날짜 경계를 넘는 재생·페이지 새로고침·광고 차단·네트워크 실패·강제 종료는 통계에 영향을 준다. 끝까지 재생된 기록도 사람이 집중해서 들었다는 증거는 아니다.

## 검증과 적용

```sh
node --test tests/audio-analytics.test.mjs
```

실제 시작, 중복 이벤트 방지, 중간 정지 후 이어듣기, 구간 이동·실패의 완료 제외, 로컬 전송 제외, GA 오류 시 플레이어 동작 보호를 테스트한다. 병합·홈페이지 배포 후 실제 사이트에서 재생하고 GA 실시간 이벤트를 확인해야 최종 연결 검증이 끝난다. 이 PR에서는 실제 GA 데이터 수신을 확인하지 않았다.
