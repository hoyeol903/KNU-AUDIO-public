# 경북대학교 데이터 소스 조사

조사일: 2026-09-30 (Asia/Seoul). 수집기를 구현하지 않고 공개 페이지의 수집 가능성만 확인했다.

## 조사 방법과 판정 기준

- 실제 HTTP 요청은 Python `requests 2.32.5`로 수행했다. 로그인 정보·브라우저 쿠키 없이 각 URL을 독립적인 GET으로 요청하고, TLS 인증서 검증을 유지했다.
- User-Agent: `KNU-AUDIO-source-research/0.1 (public-page feasibility check)`.
- 요청 전마다 1.2초 대기했다. 요청은 순차 실행했고 자동 재시도는 설정하지 않았다. 초기 샌드박스 DNS 제한은 네트워크 접근 승인 후 해결했으며 사이트 장애로 판정하지 않았다.
- 응답 상태뿐 아니라 BeautifulSoup로 응답 바이트를 읽어 실제 제목·날짜·본문·메뉴가 존재하는지 확인했다. 공지 2페이지, 상세, 학사일정 연도 변경, 식단 날짜 변경도 실제 GET으로 검증했다.
- 판정값은 `requests로 가능 / 브라우저 필요 / 불가`다. 이번 판정은 조사한 공개 페이지와 샘플에 대한 것이며 모든 게시물·첨부파일의 텍스트 추출을 보장하지 않는다.
- fixture는 `response.content`를 그대로 저장했다. 재인코딩·HTML 정리·스크립트 실행·이미지 및 첨부 다운로드는 하지 않았다. 저장된 파일을 파서 입력으로 읽으면 인터넷 없이 확인할 수 있다. 브라우저로 열면 외부 자원을 요청할 수 있다.

## 이동 규칙과 파서 참고

### 학교 학사공지

목록 링크 예시의 인자는 `doRead('stu_812', 'top', '11790744244900')`다. 원문 `doRead` 함수는 `stdViewBtin`에 `bbs_cde`, `note_div`, `bltn_no`, `menu_idx`와 검색 인자를 전달한다. 공통 JS의 `executeAction`은 `.action`과 쿼리 문자열을 붙여 `location.href`로 이동한다. 브라우저에서 JS를 실행할 필요 없이 원문 인자를 읽어 GET할 수 있다.

실제로 확인한 상세: [교직 적성 및 인성검사 결과 안내](https://www.knu.ac.kr/wbbs/wbbs/bbs/btin/stdViewBtin.action?menu_idx=42&bbs_cde=stu_812&note_div=top&bltn_no=11790744244900). 제목 `.board_view h2`, 등록 시각 `.board_info dd.date`, 본문 `.board_cont`, 첨부 `.attach a`를 확인했다. 상세 등록 시각에는 시간이 포함되므로 계약의 날짜 형식으로 변환할 때 원문을 근거로 처리한다.

`bbs_cde`나 `note_div`를 모든 글에 고정하지 말고 해당 글의 링크에서 얻어야 한다. 고정 공지는 일반 목록 및 다음 페이지에서도 중복될 수 있으므로 화면 번호 대신 출처와 원문 글 ID를 활용한다. URL에 포함된 일회성 `wbbssessionid`는 필수로 사용하지 않아도 위 GET이 성공했다.

### 전자공학부 공지

목록의 `table[summary="게시판 목록 입니다."] tbody tr`에서 제목 링크와 작성일 셀을 확인했다. 상대 링크는 목록 페이지 기준으로 절대 URL을 만들면 된다. 상세는 `td.subject`, `td.contentview`에 제목·본문이 있다.

- [이미지형 상세](https://see.knu.ac.kr/content/board/notice.html?pg=vv&fidx=105658): 본문 영역에 포스터 `<img>`와 줄바꿈만 있고 HWP 첨부 링크가 있다. HTML 텍스트만으로 포스터의 날짜·장소·마감을 얻을 수 없다. 브라우저도 자동 텍스트 추출을 해결하지 못하므로 이미지/OCR 또는 수동 입력의 별도 처리가 필요하다.
- [텍스트형 상세](https://see.knu.ac.kr/content/board/notice.html?pg=vv&fidx=105657): 설문 대상·기한·제출 방법이 HTML 본문 텍스트에 존재한다.

본문 이미지·첨부만 있는 글을 정상적인 빈 공지로 처리하지 않아야 한다. 이번 판정은 공개 HTML 접근 및 텍스트형 데이터 수집 가능성을 뜻한다. 첨부 내용 추출은 조사하지 않았다.

### 학사일정

`h2.left`의 연도, 월별 영역, `dd.list li`의 일정 설명과 `span.day`의 날짜가 근거다. `span.day`는 `MM.DD(요일)`이며 기간 종료일은 설명에 포함되는 경우가 있다. 시작·종료를 무조건 같은 날로 채우거나 표제의 학년도를 달력 연도로 대신하지 않는다.

2027 페이지는 요청 당시 13개 일정이 있었고 2026보다 적었다. 이를 완전한 2027학년도 일정이라고 가정해서는 안 된다. 학사력 PDF는 링크 존재만 확인했고 다운로드·파싱은 하지 않았다. 초기 계획의 `data/schedule.yaml` 수동 입력에 이 페이지를 원문 근거로 활용할 수 있다.

### 학식

표 선택자 후보는 `table.tstyle_me`, 날짜는 `thead .week_t`, 식사 구분은 `caption`, 메뉴는 `ul.menu_im` 안의 `<p>`와 `<br>`다. 메뉴·운영시간·가격이 같은 영역에 섞여 있으므로 모두 메뉴 이름으로 저장하지 않는다. 해당 날짜는 요청값만 믿지 말고 응답 날짜 헤더와 맞춘다.

학교 링크의 기본 식당은 `shop_sqno=46`(GP감꽃식당)이다. 페이지에서 확인한 식당 링크는 `35` 정보센터, `36` 복지관 교직원, `37` 카페테리아 첨성, `46` GP감꽃, `85` 공학관 교직원(외부업체), `86` 공학관 학생(외부업체)이다. 이번 메뉴 내용 검증은 **46과 35만** 수행했다. 나머지는 링크 존재만 확인했다.

`selDate=2026-10-05` 응답에는 10/05~10/10 날짜 표가 있으나 메뉴 표가 없다. 현재 주간 토요일 칸도 비어 있었다. 이는 메뉴가 HTML에 제공되지 않았다는 관찰이며, 휴무·미등록 등 원인은 추측하지 않는다. 날짜 표도 사라진 구조 오류와 메뉴 미제공을 구분하는 테스트 사례로 사용한다.

## JSON 주소 조사 범위

네 소스 모두 초기 HTML에서 필요한 주요 데이터가 발견되어 JS 전용 데이터 렌더링 사례는 없었다. 학교 공통 JS에 일반적인 JSON form 제출 함수는 있지만, 조사한 공지·일정의 데이터를 공급하는 JSON API라는 근거는 없다. 확인하지 않은 주소를 API로 제안하지 않는다. 브라우저 네트워크 캡처나 비공개 API 탐색은 수행하지 않았다.

## 학과·전공·단과대학 전수조사 (2026-09-30)

학교 공식 학부 대학 안내에 게시된 **학과·학부·전공 164개와 단과대학 19개, 총 183개 항목**을 모두 조사했다. 게시판을 찾은 항목은 **176개**, 독립 홈페이지·공지 게시판 미확인 항목은 **7개**, 최종 접근 실패 항목은 **0개**다. 미확인 항목도 YAML에서 삭제하지 않았다.

기존 학사공지·전자공학부·학사일정·식단 조사 내용은 유지했다. 전자공학부와 그 홈페이지를 공유하는 전공은 기존 원본을 재사용했고 재요청하지 않았다. 새 조사 범위는 학과·전공 및 단과대학 공지다.

### 기준 목록과 파일

- 기준: [학교 대학·학과·전공 안내](https://www.knu.ac.kr/wbbs/wbbs/contents/index.action?menu_idx=250&menu_url=edu%2Fschool01). 안내의 모든 학과·학부와 중첩된 전공 목록을 별도 항목으로 보존했다. 대구·상주캠퍼스를 모두 포함한다. 대학원 목록은 이 학부 대상 조사에 포함하지 않는다.
- 보완: 단과대학 홈페이지의 학과 소개·메뉴에서 실제 링크를 확인했다. 예: [정보·컴퓨터교육과 소개](https://home.knu.ac.kr/HOME/education/sub.htm?nav_code=edu1748406324), [IT 자율학부 공동 소개](https://home.knu.ac.kr/HOME/it/sub.htm?nav_code=it1739940297). 학교 안내에서 홈페이지가 `#`였어도 보완 근거가 있으면 주소를 기록했다.
- `data/departments.yaml`: 요구한 7개 필드에 단과대학/학과 구분용 `kind`와 분류·공유·미확인 사유인 `notes`를 덧붙인 목록이다. `college`는 공식 안내의 소속 묶음 이름을 그대로 사용한다. 독립 학부는 해당 안내 묶음 이름을 사용한다.
- `docs/departments-audit.json`: 항목별 요청 URL, 최종 URL, HTTP 상태, 인코딩, SHA-256, 후보 공지 링크와 판단 근거를 보존했다. 보완 조사에서 참고한 주소와 초기 네트워크 실패도 포함한다.

### 조사 방식

`requests` GET으로 로그인 없이 홈페이지 → HTTP/메타 refresh 이동 → 프레임 실제 주소 → 공지 메뉴를 확인했다. 프레임이나 이동 코드 자체를 JS 데이터 렌더링으로 판정하지 않았다. 동시 연결은 최대 4개, 같은 서버는 이전 응답 후 다음 요청까지 1.1초 이상 쉬었다. 서버 IP를 기준으로 잠금을 공유해 여러 `*.knu.ac.kr` 별칭이 같은 서버를 쓰는 경우도 간격을 지켰다. 별도 실행 사이에도 요청은 겹치지 않았다. User-Agent를 명시했고 TLS 검증을 유지했다. 실패 URL은 응답 기록을 보존하며 재시도 2회 이내로 확인했다.

첫 조사 후반의 DNS·연결 오류는 짧은 묶음으로 재확인하여 복구됐다. 최종 `unreachable` 집계는 최초 실패가 아니라 마지막 확인 결과다. 성공한 원본은 캐시로 재사용했다. 조사 스크립트는 임시 작업 공간에서만 실행했고 저장소에 수집기·운영 코드·새 의존성을 추가하지 않았다.

### HTML 목록과 JavaScript

글이 있는 목록에서는 제목·날짜·상세 링크 또는 이동 인자가 원본 HTML에 존재했다. 경상대학과 경상대학 자율학부의 두 공지 목록은 `.list_nodata`에 “등록된 내용이 없습니다.”가 명시된 정적 빈 목록이었다. 두 원본은 `knu-cms/경상대학_빈목록.html`, `경상대학 자율학부_빈목록.html`과 `빈목록_metadata.json`으로 추가 저장했다. 이를 JS 렌더링이나 읽기 실패로 처리하지 않는다. CMS의 `frameset`, 메타 refresh, 공지 탭 표시, URL 이동, 첨부 팝업의 AJAX는 있었지만 이를 공지 목록의 JS 전용 렌더링으로 분류하지 않았다. JS 전용 목록으로 확정한 항목은 없다. 별도 JSON API는 확인하지 않았으며, 없는 것으로 단정하지 않는다. 각 항목의 `rendering`, `detail_url`, 후보 메뉴와 응답 사실은 audit 파일에서 확인할 수 있다.

### 공유 게시판과 대표 주소 선택

- 여러 공지 메뉴가 있으면 학부·학과·학사 공지를 우선하고, 일반 공지로 이어지는 메뉴를 확인했다. YAML의 `notice_url`은 대표 주소 1개다. 학사/장학/일반/대학원처럼 게시판이 나뉜 곳의 발견된 메뉴는 audit의 `notice_candidates`에 함께 남겼다. 이 대표 주소 하나만으로 모든 분류 게시판을 수집했다고 해석하지 않는다.
- 전자공학부와 7개 세부 전공은 같은 공지를 공유한다. 건축학부와 2개 전공, 의과/치과/수의과/간호/약학의 대학과 학과, 일부 자율학부도 공유 주소가 있다. 실제 요청·수집은 주소 기준 중복을 제거해야 한다.
- 지구시스템과학부의 공식 링크는 자연과학대학 내부 소개 페이지다. 학부 항목에는 그 사이트의 단과대 공지를 기록했으며, 지질학·천문대기과학·해양학 전공의 게시판은 별도 항목으로 조사했다.
- IT대학의 대표 공개 게시판은 `NEWS/게시판`으로 표시된다. 학생 안내·채용 등 소식을 포함한다. IT 자율학부·IT 첨단자율학부의 `학부 공지사항` 주소는 별도로 확인해 두 학부 항목에 기록했다.

### 오프라인 검증
